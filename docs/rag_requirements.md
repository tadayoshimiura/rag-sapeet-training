# RAG システム 要件定義（ドラフト）

## 目的
- テキスト・音声・映像・PDFを対象に、検索と要約/QAを行うRAG基盤を構築する。
- AWS / Azure / GCP を設定切替のみで運用できるマルチクラウド対応の設計とする。

## 機能要件
- **ドキュメント保存**: オブジェクトストレージ（S3 / Blob / GCS など）に原本を保管し、メタデータを別途管理。
- **ベクトルデータベース**: 埋め込みベクトルとメタデータを保存し、kNN / Hybrid 検索を提供。
- **オーケストレーター**: インジェスト、検索/QA のワークフローを制御。
- **レトリーバー**: クエリを埋め込み→検索（BM25+ベクトル）→再ランキング。
- **ジェネレータ**: 取得コンテキストを用いて LLM が回答生成。
- **前処理/インジェスト**:
  - テキスト/PDF 抽出、音声・映像の文字起こし（STT）。
  - チャンク分割（段落/時間/長さベース）、正規化。
- **モデル**:
  - LLM: GPT 系 / Claude / Gemini / Bedrock 系など切替可能。
  - Embedding: OpenAI / Bedrock / CoHere / Vertex Embeddings 等。
  - STT: Whisper / Azure Speech / Transcribe / Vertex Speech-to-Text 等。
- **API**: Ingest API、Search/QA API、管理API（ドキュメント・メタデータ・モデル設定）。

## 非機能要件
- **セキュリティ**: IAM/ロール、TLS、監査ログ、PII マスキング、保持・削除ポリシー。
- **可観測性**: メトリクス、ログ、トレース（OpenTelemetry）、評価指標（groundedness など）。
- **スケーラビリティ**: バッチ/ストリーミングインジェスト、非同期ジョブ（キュー/イベント）。
- **コスト最適化**: 高品質/経済的インデックスの切替、キャッシュ、ジョブ優先度。
- **バージョニング**: ドキュメント/インデックス/モデル設定の世代管理。

## マルチクラウド切替の方針
- 基本は「メインクラウドへバイアス」：AWSベースなら可能な限りAWSサービス、AzureベースならAzureサービスを優先採用。必要に応じて他クラウド/サードパーティをスポット利用できる設計。
- ストレージ/ベクトルDB/LLM/Embedding/STT に共通IFを定義し、プロバイダごとにアダプタ実装（メインクラウドをデフォルトに設定）。
- IaC（Terraform/Pulumi）でクラウド差分を吸収しつつ、メインクラウドのリソースを優先デプロイ。
- シークレット管理は各クラウド標準（Secrets Manager / Key Vault / Secret Manager）。
- 監視は CloudWatch / Azure Monitor / Cloud Monitoring を抽象化しつつ OpenTelemetry を併用。

## 処理フロー（概要）
1. アップロード: ユーザがドキュメント/音声/映像/PDF を送信し、ストレージに保存。
2. パース & 文字起こし: Parser がテキスト抽出、必要に応じて STT 実行。
3. チャンク化: Chunker がルール/長さベースで分割。
4. 埋め込み生成: EmbeddingClient がベクトル化。
5. インデックス: VectorStoreClient に upsert（メタデータ付き）。
6. 検索/QA: Retriever が検索→再ランク、Generator が LLM で回答生成。

## 未確定事項（要確認）
- ベクトルDB の優先候補と制約（スキーマ/ACL/リージョン）。
- 優先プロバイダ（LLM/Embedding/STT）とコスト上限。
- セキュリティ要件の厳格度（社外秘/PII）。
- 評価指標と SLO（遅延/ヒット率/コスト）。
